# Pending HIPAA changes — what is built, and how it goes live

Everything below is **built and tested but NOT deployed**. It lives in the worktree
`C:\sistems\projects\mrcv-hipaa-phase1` (branch `hipaa-phase1`). The live checkout
`C:\sistems\projects\MR_Computer-Visuion` is unchanged (live DB at migration 052).

Two ways to go live:

* **A. New production host (recommended, any provider)** — the encrypted stack:
  [`ops/deploy/README.md`](deploy/README.md) + data move [`ops/migrate/README.md`](migrate/README.md).
  This is the only path that delivers encryption at rest and TLS on every hop.
* **B. Interim update of the current Windows host** — the application changes only
  (below). No TLS / encrypted storage: Docker Desktop on Windows is not a production host.

Do not copy files into the live checkout piecemeal: the backend runs `uvicorn --reload`
with `./backend` bind-mounted, so every copied file goes live the moment it is written.

## Behaviour changes users will notice

- New pages: **Emergency Access** (doctors), **Emergency Access Review**, **Patient Rights**, **Audit Review** (admins).
- Everyone is signed out once at the switch (old tokens in localStorage are ignored; sign in again).
- A signed report's PDF no longer changes after signing (it is the signed copy); its file name ends in `_signed`.
- DICOM files downloaded from the viewer carry the MRN as patient name.
- Webhooks: no `patient_id` unless `WEBHOOK_INCLUDE_PATIENT_ID=true`; `http://` rules stop firing.
- `/api/debug/medgemma/*` only with `DEBUG_ROUTES_ENABLED=true`.
- (Batch 4) Every account must enrol MFA at next sign-in (production).
- (Batch 4) SR / FHIR export and "share" answer 409 until the report is signed, or while the
  patient has a restriction on that channel.
- (Batch 4) New workspaces stay *suspended* until their BAA is recorded (production).
- (Batch 4) The viewer no longer shows birth date / address in DICOM tag browsers.
- (Batch 4) New items: Patient Rights → request register and restrictions; tenant page →
  BAA; Admin → Metrics → AI quality.

## B. Interim update of the current host (≈10 min)

1. **Idle + backup.**
   ```bash
   cd C:/sistems/projects/MR_Computer-Visuion
   docker compose exec -T postgres psql -U mri_admin -d mri_platform -At -c \
     "select count(*) from job_runs where status not in ('completed','failed','cancelled')"   # expect 0
   docker compose exec -T postgres pg_dump -U mri_admin -d mri_platform -Fc > ../backups/pre_hipaa_batch3.dump
   ```
2. **Build images first** (running containers untouched): copy `ui/`, `backend/pyproject.toml`
   from the worktree, then `docker compose build ui backend worker` (`pyzipper` is new).
3. **Migrations 053–057** (additive: new tables and columns, a permission, the extended
   `studies` referral policy, the shadow check constraint): copy
   `backend/alembic/versions/05[3-7]_*.py`, then
   `docker compose exec -T backend alembic upgrade head`.
4. **Code in one go**: everything under `backend/app` and `backend/tests` that differs,
   `orthanc/on_stable_study.lua`, `nginx/templates/default.conf.template` (new WADO routes
   through the backend), `.env.example`, `.gitattributes`, `ops/`, the new prod files.
5. **Recreate**: `docker compose up -d --no-deps backend beat worker ui nginx`
   (orthanc only if you want the Lua change now: `docker compose up -d --build --no-deps orthanc`).
